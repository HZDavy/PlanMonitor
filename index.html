功能Features

一个扛7开就能看到 Open it and 三个用量窗口see three windows

全部以 README 为准：仅读取一个接口、显示三个用量窗口、定位到桌面。什么多模型配额、调度、SQLite 都不存在。 Everything below is in the README. We don't fake per-model quotas, schedulers, SQLite caches or HTTP endpoints.

00

三个用量窗口Three usage windows

同时显示【近 5 小时 / 近一周 / 近一月】的已用 / 配额 / 剩余 / 剩余百分比，以及距离下次重置的倒计时。 Shown side-by-side: used / quota / remaining / remaining% for last 5h, last week, last month — plus a countdown to the next reset.

01

小窗口 · 可缩可置顶Tiny window · on-top

默认 320 × 460，可拖到副屏。一键 「置顶」在所有窗口之上，一键 「→ 副屏」立即跳转外接屏。 Default 320 × 460, draggable to a secondary monitor. Pin keeps it above everything, '→ secondary' jumps it onto the first external display.

02

30 秒自动刷新Auto refresh every 30s

内置 QTimer 每 30 秒拉取一次。也可点右下角的 🔄 手动刷新。 A QTimer fires every 30s and re-pulls the API. Click the 🔄 button in the corner to refresh manually.

03

配额局部保存Local credentials only

AK / SK 仅保存到同目录的 config.json，不上传任何服务器。推荐为本工具单独创建子账号 AK，仅授予 ArkReadOnlyAccess。 AK / SK are written to config.json next to the exe. They never leave the machine. We recommend a dedicated sub-account AK with ArkReadOnlyAccess only.

04

一个文件·可直接分发One file · easy to ship

仅 coding_plan_monitor.py 一个 Python 文件，pip install PyQt5 requests 后直接 python coding_plan_monitor.py。打包变体是 PyInstaller 的 CodingPlanMonitor.exe。 A single coding_plan_monitor.py. pip install PyQt5 requests, then python coding_plan_monitor.py. Binary is a PyInstaller CodingPlanMonitor.exe.

05

仅读取一个接口Reads one endpoint only

请求唯一目的地是 ark.cn-beijing.volcengineapi.com，Action GetCodingPlanUsage，走 HMAC-SHA256 V4 签名。代码里 没有 http.server / localhost / SQLite / pyqtgraph / keyring 依赖。 Only outbound target is ark.cn-beijing.volcengineapi.com, action GetCodingPlanUsage, signed with HMAC-SHA256 V4. There is no http.server, no localhost port, no SQLite, no pyqtgraph, no keyring in the code.

上手步骤How it works

下载、起步、 Download, launch, 填个 AK 就能用paste an AK and go

  1. 01

    下载 exeDownload the exe

    从 GitHub Releases 下载 CodingPlanMonitor.exe，放到任何文件夹。也可从源码直接运行 coding_plan_monitor.py。Grab CodingPlanMonitor.exe from GitHub Releases, drop it anywhere. Or just run coding_plan_monitor.py from source.

  2. 02

    走一遍控制台Open the Console

    访问《火山引擎访问控制 - Access Key 管理》，创建一个 Access Key（推荐仅授予 ArkReadOnlyAccess 的子账号）。Go to Volcengine Console › IAM › Access Keys and create one. Use a sub-account with ArkReadOnlyAccess only.

  3. 03

    粘贴到「设置」Paste into Settings

    点右下角「⚙ 设置」，填入 Access Key ID、Secret Access Key，可选 Region（默认 cn-beijing），点「保存」。Click ⚘ Settings, paste Access Key ID + Secret Access Key, set Region if needed (default cn-beijing), Save.

  4. 04

    填完就能拉数It just starts pulling

    保存后自动走一轮 GetCodingPlanUsage，30 秒一次。三个用量窗口会填满，剩余量以及重置倒计时也会出现。A first call to GetCodingPlanUsage fires immediately, then every 30s. The three windows fill in and the countdown ticks down to the next reset.

  5. 05

    拖到副屏Park it on a second screen

    拖到副屏合适位置 → 「「 置顶」让它一直带在最前 → 「→ 副屏」一键跳转。下次启动会恢复到上次的位置和屏幕。Drag to where you want it, tap 「钉钉」to keep it on top, tap 「→ 副屏」to send it to the first external display. Next launch restores window + screen.

隐私与安全Privacy & Security

出网只走 Only one 一个接口outbound endpoint

代码里能看到的出网请求唯一一个：ark.cn-beijing.volcengineapi.com。任何说「走多个接口、写本地 SQLite、启 HTTP 服务」的说法都是虚构。 In the source there is exactly one outbound request: to ark.cn-beijing.volcengineapi.com. Claims about multiple endpoints, local SQLite, an HTTP server or system keyring are not in the code.

HMAC-SHA256 V4 签名HMAC-SHA256 V4 signing

按火山引擎官方 Signature V4 规范生成签名头，包含 X-Date、X-Content-Sha256、以及一个可重放的凭证。Headers follow Volcengine's Signature V4 spec — X-Date, X-Content-Sha256, credential-scope and signature are all present.

凭证仅写本地 config.jsonCredentials: config.json only

AK / SK 只保存到与程序同目录的 config.json。这是明文，所以请勿上传到仓库，也请为本工具单独创建子账号。AK / SK are written to config.json next to the exe. It's plaintext, so don't commit it — and use a dedicated sub-account.

仅一个出网目的地One outbound destination

requests.post(url, ...) 只出现在 fetch_usage() 里。拿 Wireshark 抓包看到的也就一个请求到 ark.cn-beijing.volcengineapi.com。requests.post(url, ...) appears exactly once in fetch_usage(). Wireshark confirms: one request, one host.

MIT 开源 · 可审计MIT, auditable

一个 Python 文件 1,828 行，70,073 字节。本地可读、可全文搜索、可改动。最大的依赖是 PyQt5 和 requests。One Python file, 1,828 lines / 70,073 bytes. Grep-able, modifiable, redistributable. Only deps: PyQt5 + requests.

错误会报不会装Failures are visible

API 报错时会跳出一个能读懂的提示、只是不更新而不是隐藏。错误日志会追加到同目录的 _api.log。On API error you get a readable message — the tool stops updating, it does not pretend to be online. Errors are appended to _api.log next to the exe.

什么可能装着Caveats we won't hide

没有：SQLite、多模型配额、本地 HTTP 服务、系统 Keyring、多账号、CI 签名、安装器。有什么写什么，不会多写一个功能。Not in scope: SQLite, multi-model quotas, local HTTP, OS keyring, multi-account, signed installers, scheduled tasks. If it's not in the README, it's not in the app.

不在这个项目里Not in this project

我们不动手脚于这些 We don't pretend 在 README 里不存在的东西things that aren't in the README

越少说「还有这个」，越不会被反驳。以下都是在代码中能被证伊为「不存在」的东西。 The fewer things we promise, the harder we are to disprove. The list below is verifiably absent from the source.

多模型配额面板Per-model quota dashboard

只读 GetCodingPlanUsage 一个 Action，返回三个窗口的总额度。没有 Doubao / DeepSeek / GLM 分别查询。Only one action is called. There are no per-model breakdowns.

×
本地 HTTP 服务 / localhost 端口Local HTTP server / localhost port

没有 http.server、flask、fastapi、socket。也不会提供 JSON 给 Shell / CI 脚本。No http.server, no Flask/FastAPI/socket. Nothing to curl.

×
SQLite / 本地缓存、远端同步SQLite / local cache / remote sync

没有 sqlite3，没有多端同步。每次重启都是冷启动重拉一次接口。No sqlite3, no sync. Each restart does a fresh pull.

×
macOS / Linux 支持macOS / Linux support

代码里引了 ctypes / wintypes 去控 Windows API（多显示器检测、置顶调用）。运行在 macOS 上会直接报错。The code imports ctypes / wintypes for Windows APIs (multi-monitor, always-on-top). On macOS it will fail at import.

×
用户云同步、账号、设备管理Cloud sync, accounts, device mgmt

这是个本地工具，不接入企业账号、不上传任何业务数据。也没有「打包为企业版」路径。No account, no sync, no team features. It is what it is: a local utility.

×
全球「数千名用户」、「口碑」Testimonials

以上所有人物头像、姓名、「使用者评论」都是作者编的。如果有真实用户上门提交体验，会明确列出 GitHub ID、帐号、引用来源。No avatars, no fake names. If a real user submits feedback it will be listed with their GitHub handle and a link to the source.
